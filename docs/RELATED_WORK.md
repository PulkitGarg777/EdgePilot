# EP-009 related-work matrix

Research review: 29 September 2026. Companion: [overlap assessment](RESEARCH_OVERLAP.md). Scope: the eleven works linked in the original Word roadmap, plus one targeted preemption reference found while checking the Age of Information foundation. This is a bounded literature review, not an exhaustive novelty search or reproduction of the papers' results.

The links below identify the primary-source versions examined. Methods and experimental sections were inspected for the compared claims; section locators make the evidence reviewable. Paper results are author-reported. The final column is our interpretation relative to EdgePilot. “Not established” means the inspected evidence does not establish that property; it is not proof of absence from every version or related work. Unverified host specifications remain explicit gaps.

## Scheduling and asynchronous robotics

| Work / primary source and locator | Mechanism and assumptions | Hardware / evaluation / baselines | Limitations and EdgePilot overlap (our assessment) |
| --- | --- | --- | --- |
| **CoMuRoS**, Borate et al., [LLM-Based Generalizable Hierarchical Task Planning and Execution for Heterogeneous Robot Teams with Event-Driven Replanning](https://arxiv.org/html/2511.22354v2), v2, June 2026; III-IV. | Central task manager, robot-level planning, ROS2 skills, and contextual event classification drive replanning and recovery. Assumes configured capabilities, working primitives, and event perception. | Go2, TurtleBot Burger/Waffle and OpenManipulator-X hardware; simulation and textual tasks. Evaluates multiple LLM backends; hardware recovery uses GPT-4o. Related-system feature comparisons are distinct from controlled scheduler baselines. Inference-host specifications not verified. | Already covers relevant/irrelevant events and resumed tasks. Hardware task recovery is richer than EdgePilot's scene. The inspected evaluation does not establish a measured residual-service versus stop/restart scheduling policy. Declared dependency checks alone are not a novelty claim. |
| **VLASH**, Tang et al., [Real-Time VLAs via Future-State-Aware Asynchronous Inference](https://arxiv.org/html/2512.01031v2), v2, July 2026; IV-V, appendix B. | Rolls robot state forward to the expected execution time; temporal-offset training teaches use of that state alongside the current image. Action quantization groups motion steps. Requires predictable robot evolution and training data. | Kinetix/LIBERO; Galaxea R1 Lite and SO-101; RTX 5090 laptop experiments and H100/4090 timing comparisons. Sync, naive async, RTC baselines; multiple VLA backbones. | Addresses action-chunk alignment and motion continuity. EdgePilot schedules discrete skill plans with a conventional executor. Asynchrony and latency compensation already exist; motion speedups cannot be transferred to EdgePilot's fixed-duration skills. |
| **FutureRTC**, Jiang et al., [Real-Time Robot Execution with Anticipatory-Conditioned Action Chunking](https://arxiv.org/html/2607.24008v1), July 2026; Methodology, Experiments, Hardware Setup, Limitations. | Learns state correction and future visual features, with a policy-consistency loss while keeping the base policy frozen. Requires adapter training; “plug-and-play” does not mean training-free. | RTX 4090 training; Kinetix/LIBERO; AgileX Cobot Magic dual-arm trials. Naive async, temporal ensembling, BID, RTC, T-RTC, VLASH, REMAC comparisons. | Authors identify difficulty when independent external agents dominate visual change. Relevant to stale observations, but predicts execution context rather than choosing which high-level request to finish or replace. EdgePilot currently has direct state and no learned predictor. |
| **RTGen scheduling study**, Karami et al., [Exploring the Dynamic Scheduling Space of Real-Time Generative AI Applications on Emerging Heterogeneous Systems](https://arxiv.org/html/2507.14715v1), July 2025; 4-5, Tables 3-4. | Profiles backend costs and simulates mixed generative/periodic workloads. Compares FCFS-AOT, FCFS-DYN, EDF-AOT, EDF-DYN, and First Token First; the latter prioritizes prefill to limit starvation. | Ryzen AI 9 365, 24 GB, XDNA 2 NPU, Radeon 880M. Measured model profiles feed a Python scheduling simulator. Metrics include deadline violations, TTFT, and token latency. | Policy outcomes rely on the simulator and profiled costs. Already motivates phase-aware resource scheduling; EdgePilot adds task-validity questions in a single-worker setting. Layer preemption here does not verify llama.cpp computation cancellation. This is not the unrelated RTGen object detector. |
| **ActionFlow**, Dai et al., [A Pipelined Action Acceleration for Vision Language Models on Edge](https://arxiv.org/html/2512.20276v1), December 2025; 3-4. | Pipelines requests across control timesteps, combines prefill/decode work, and uses packed execution plus a shared KV ring buffer. Assumes model/runtime access sufficient for fused operations. | OpenVLA-7B on Jetson AGX Orin 64 GB and RTX 5090. Standard autoregressive inference and naive pipeline baselines; FPS and LIBERO success checks. | Evaluates throughput and task correctness, not a stop/restart decision for superseded symbolic goals. Its Table 1 time-unit label appears inconsistent with FPS reciprocals; avoid importing those timing values without clarification. EdgePilot's one-active-request adapter offers no equivalent pipeline mechanism. |

## Guardrails and grounded skills

| Work / primary source and locator | Mechanism and assumptions | Hardware / evaluation / baselines | Limitations and EdgePilot overlap (our assessment) |
| --- | --- | --- | --- |
| **SafePlan**, Obi et al., [Leveraging Formal Logic and Chain-of-Thought Reasoning for Enhanced Safety in LLM-based Robotic Task Planning](https://arxiv.org/html/2503.06892v1), March 2025; IV-VI. | Prompt screening and logic-guided LLM reasoners generate/check invariants, preconditions, and postconditions before code execution. Relies on scene descriptions and reasoner correctness. | GPT-4o/Gemini prompt comparisons on 621 cases; AI2-THOR code checks against direct execution without verification. Up to three checking attempts. Host hardware not verified. | Logic-guided LLM critique should not be equated with a complete independent proof. Safe-task acceptance and refusal matter alongside intercepted hazards. EdgePilot's deterministic dispatch checks serve a narrower purpose; generic preconditions/guardrails are established prior work. |
| **SENTINEL**, Zhan et al., [A Multi-Level Formal Framework for Safety Evaluation of Foundation Model-based Embodied Agents](https://arxiv.org/html/2510.12985v3), July 2026; 2-4, appendix D. | Separates semantic interpretation, LTL plan checking, and CTL checking of trees built from sampled execution trajectories. Depends on specifications and grounded state propositions. | VirtualHome/AI2-THOR, multiple FM agents, LLM-as-Judge feedback and per-trajectory LTL comparisons; illustrative Franka case study. Compute-host specifications not verified. | Formal conclusions are relative to the represented constraints and sampled/modelled behavior. Broad real-world transfer remains open. EdgePilot should retain separate plan, execution, refusal, and task-success outcomes; adding checks is not by itself a new safety framework. |
| **SayCan**, Ahn et al., [Do As I Can, Not As I Say: Grounding Language in Robotic Affordances](https://arxiv.org/html/2204.01691v2), August 2022; 3-5. | Combines language-model skill scores with learned affordance values, selects a skill, executes it, then repeats. Assumes a trained skill library and meaningful success estimates. | Everyday Robots mobile manipulator, 540B PaLM, two kitchen settings and 101 instructions. Comparisons remove affordance or language components; planning and execution success are separate. Serving hardware not verified. | Establishes language-guided composition of bounded skills and state grounding. EdgePilot uses explicit predicates and conventional skills instead of learned affordances. The fixed two-station mission also warrants a symbolic baseline to determine whether LLM planning adds value. |

## Measurement and scheduling foundations

| Work / primary source and locator | Mechanism and assumptions | Hardware / evaluation / baselines | Limitations and EdgePilot overlap (our assessment) |
| --- | --- | --- | --- |
| **MELTing point**, Laskaridis et al., [Mobile Evaluation of Language Transformers](https://arxiv.org/html/2403.12844v4), July 2024; 3-5. | Automated evaluation separates prefill/generation, memory, power, thermal behavior, and accuracy. Comparisons span models, quantization levels, and runtime backends. | Galaxy S23, Pixel 6a, iPhone 14 Pro/SE, Jetson AGX Orin/Orin Nano; MLC-LLM, llama.cpp, LLMFarm. Phone power uses external Monsoon instrumentation; Jetson measurements use board sensors. | Findings depend on device, runtime version, and thermal conditions. Supplies measurement discipline, not robot request scheduling. EdgePilot's HTTP elapsed time cannot substitute for sensor-based energy or GPU compute measurements. Missing telemetry must remain visible. |
| **Sarathi-Serve**, Agrawal et al., [Taming Throughput-Latency Tradeoff in LLM Inference with Sarathi-Serve](https://arxiv.org/html/2403.02310v3), June 2024; 3-5; [OSDI publication](https://www.usenix.org/conference/osdi24/presentation/agrawal). | Chunked prefills and mixed batches preserve ongoing decode progress while admitting work. Requires scheduler access inside the serving engine and compatible concurrent requests. | Single/multiple A100 configurations with Mistral-7B, Yi-34B and larger models; vLLM comparisons and other batching schedules. Measures serving capacity under latency constraints. | Optimizes serving rather than goal relevance. The compared vLLM behavior is that paper's implementation snapshot. EdgePilot can learn phase/cost measurement concepts; its HTTP adapter cannot inherit these batching gains or cancellation semantics. |
| **Age of Information survey**, Yates et al., [Age of Information: An Introduction and Survey](https://arxiv.org/html/2007.08564v1), July 2020; packet management, LGFS, energy-constrained updates. | Measures age from generation time of the newest delivered update. Studies replacement, preemption, sampling, and resource constraints under explicit arrival/service assumptions. | Analytical queue models and numerical comparisons: FCFS, small buffers, latest-generated service and preemptive variants. No single hardware benchmark applies. | Already covers keeping the newest waiting update. Preemption benefits depend on service distributions and resource costs. EdgePilot's goal latency is not automatically AoI: an old plan can remain applicable, while a recent plan can violate current preconditions. |
| **Targeted follow-up: When to Preempt**, Banerjee and Ulukus, [When to Preempt in a Status Update System?](https://arxiv.org/html/2402.00845v2), May 2024; II-IV. | A causal MDP uses monitor age and service age; analyzes always-preempt conditions and threshold policies using service statistics. Assumes discrete time, generate-at-will updates, and IID service times. | Theory/numerical policies, including always-preempt and threshold structures; no robot hardware. | This is a direct novelty boundary for “remaining-time-aware cancellation.” It does not establish EdgePilot's semantic applicability model or measured terminal-acknowledgement cost. Its optimality results cannot be transferred without checking those assumptions. |

## Interpretation and follow-through

The comparison supports a narrower question about useful planning work under changing task state. It does not establish that a novel scheduler is needed. [RESEARCH_OVERLAP.md](RESEARCH_OVERLAP.md) records the hypothesis and evidence needed for EP-011.

Baseline choice should follow the mechanism being tested: newest-pending and tuned age/service thresholds for freshness; task-aware cancellation for relevance; symbolic planning for the constrained mission; common guardrails for all policies. Reimplementing all eleven systems would introduce unrelated models, hardware, training, and control semantics.

The named corpus is covered. Before a publication-level novelty claim, expand the search around semantic/value-of-information scheduling, metareasoning, and task-aware preemption. A claim that no prior system combines these ideas is not supported by this bounded review.
